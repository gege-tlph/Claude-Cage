Cage lite 0.2.4，只提供 Windows 版（Windows 10 22H2、Windows 10 LTSC 2021 或 Windows 11，x64）。

## 安装

1. 已装 0.2.3 的，可以在应用内更新（「设置 > 关于」），也可以下载 `Cage-0.2.4-windows-amd64-setup.exe` 覆盖安装，环境和数据都会保留。
2. 网络不好、首次安装总在下载时失败的，可以改用完整包 `Cage-0.2.4-windows-amd64-full-setup.exe`（约 1.6 GB）。它和普通安装包是同一套签名程序，另外带着首次安装要下载的 Debian 13 系统镜像、Debian 和 NodeSource 软件包，以及 mise、GitHub CLI、code-server。安装环境时这些不再下载，只有 Claude Code 仍在安装时下载。装好的环境和用普通安装包装的一样。
3. 已经装好环境的，不需要完整包。应用内更新仍然只用普通安装包。
4. 新安装的，在安装选项页勾选"信任 Cage lite 发布者证书"（默认已勾选），Windows 弹出确认时选"是"。也可以手动导入本页附带的 `cage-lite-signing.cer`：

```powershell
Import-Certificate -FilePath .\cage-lite-signing.cer -CertStoreLocation Cert:\CurrentUser\Root
```

## 与 0.2.3 相比

完整包
- 新增完整安装包，发版时在 GitHub 上自动编出：在 Linux 机器上用同一版本联网装一遍环境，收集下载过的文件，再和签好的普通安装包里的程序一起打包，用同一张证书签名。
- 首次安装的四个阶段照常进行。区别只是下载的文件已经在本机：软件包放进 APT 的下载缓存，开发工具放进工具下载目录，都是联网安装本来存放它们的位置，安装完成后也保留在那里。
- 首次开机时，Lima 自己的装包步骤不再联网，改为在安装文件送进环境后从本地补装。
- 附 `Cage-0.2.4-full-packages.tsv`（所带软件包的源码包名、版本和来源）和 `Cage-0.2.4-full-sources.txt`（源码的获取方式，以及三年内应要求提供源码的书面承诺）。

状态栏与操作日志
- 窗口底部新增全局状态栏：正在做的事、结果和出口状态都在这里，等待类按钮统一用转圈和完成动画。
- 新增"操作日志"窗口（原"操作详情"）：简易视图写每一步的结果；高级视图按等级列出本次运行的事件，往上翻时再补更早的。日志可一键复制，失败时可以直接导出诊断包。
- "设置 > 环境与恢复 > 操作日志"可以选日志等级。
- "日志与诊断"改名"诊断包"。诊断包带上 Lima 主机代理、串口日志和状态文件（已去掉敏感内容）。

失败提示
- 失败提示改为三行：哪一步失败、原因、怎么办，按严重程度分红、橙、蓝三级，附实用的工具按钮。
- 覆盖启动和停止环境、代理与出口、安装、Claude Desktop、文件传递和应用更新。原因写到具体的节点、阶段或电脑状态，例如磁盘空间、可用内存、上次的环境后台仍在运行。
- 重试按钮会把整个流程走完，不只重做出错的那一步；例如"重启环境"会先停止、等待，再启动到就绪。
- 环境的虚拟磁盘满了时，不再误报为电脑磁盘空间不足。

设置
- 设置页底部有统一的提交栏；有未应用的修改时点 ←，会留在设置里，提交栏闪烁提醒。
- "网络与代理"重新排版，链式代理可以直接编辑：用上移、下移调整顺序，链路里的箭头用图标表示。
- 链式代理的前置可以设为自动切换：选整份订阅或自选节点，故障转移时可以调整顺序（来自上游 #1063）。
- 首次安装的进度卡片显示整体进度和当前第几步，失败用三行提示，装完后直接进入工作台。
- 首次设置里网络按钮改叫"网络代理"，代理步骤的输入框和设置页一致。

代理
- 出口检测能识别 REALITY 认证失败，并说明是所选节点、前置还是出口节点（上游 #809）。
- MASQUE 节点和分享链接暂不支持，导入时会说明原因；节点全是 MASQUE 时建议改用其他协议的节点（上游 #974）。
- Surge 配置里的 VLESS 节点可以导入（上游 #1081）。
- 测速超时后会换一个备用地址再测一次，Ferry 出口巡检也用这个做法（上游 #1125）。
- 前置是自动组时，Ferry 的出口跟随和连接 Ferry 照常工作；本机中转只能作第一跳。

终端与 Claude
- 暂停的 Claude 对话会保留它的账号，在原终端可以继续，电脑和手机上都能点"继续对话"（上游 #1060）。
- 可以从电脑本机的终端调用 Cage lite 环境里的 Claude Code；新增 `cage start`，后台启动和 Claude 账号授权分开（来自上游）。
- 内置 commands 插件可以选 shell（PowerShell、pwsh、Git Bash、cmd）。中文 Windows 上命令输出不再乱码；没装 pwsh 或 Git Bash 时先报错，不再先弹审批框。
- 终端可以嵌套分屏，分屏大小可以拖动调整（上游 #1138）；侧栏的项目预览里保留已打开的终端（上游 #1128）。
- 专属出口账号可以连接电脑上的 computer MCP（上游 #1137）。
- Windows 本机终端里按 Ctrl+Z 不再断开连接。
- Windows 上 `cage update` 只检查新版本，安装请到"设置 > 关于"；没有 Hyper-V 的电脑上运行 `cage.exe` 不再先打一行 VSock 报错。

环境与 Windows
- 主机代理仍在运行时不再改写画面端口，停止环境会真正停掉它（0.2.3 里画面端口会漂移）。
- 带触屏的电脑上，远程画面不再同时显示两个鼠标指针（#351）。
- Windows 自动内存按可用内存分配；可用内存不足 3 GiB 时，启动前就说明（上游 #1082）。
- 环境存储换到其他盘以后，"重置环境与换机"不再失败（上游 #1107、#1111）。
- 下载速度不再显示为 NaN，任务状态始终能读取（上游 #1104）。
- cloud-init 打出指纹横幅后，诊断输出和安装进度不再被整段隐藏（上游 #1105）。
- Cage lite 在前台时，从 WPS 表格复制的单元格不再被当成图片（上游 #1079）。
- Windows 上的 Claude Desktop 里，逐字上屏的拼音词组会合并，点击后的第一次输入也正常（上游 #940）。
- 应用更新：下载进程确认退出后才报告失败，下次更新能重新开始（上游 #1096）。
- 手机端：iOS 扫码线不再越界，Android 不再有白边，从后台恢复和重新配对不再复用旧连接（上游 #833）；手机浏览器改为运行真实的有头浏览器（上游 #1008）。
- 远程 SSH 模式下，本机的桌面窗口可以管理远程插件（上游 #1129）。

英文界面
- 这次新增的界面文字和后台提示都有英文。

## 校验与源码

- `SHA256SUMS` 列出本页所有文件的 SHA-256；`cage-lite-release.json` 是应用内更新读取的版本清单。
- 安装包内的 mihomo（GPL-3.0）和 QEMU（GPL-2.0）的对应源码附在本页。完整包所带 Debian 软件包的源码说明见 `Cage-0.2.4-full-sources.txt`。Cage lite 本身的源码在本仓库，以 MIT 许可发布。
