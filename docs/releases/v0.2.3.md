Cage lite 0.2.3，只提供 Windows 版（Windows 10 22H2、Windows 10 LTSC 2021 或 Windows 11，x64）。

## 安装

1. 已装 0.2.2 的，可以在应用内更新，也可以下载 `Cage-0.2.3-windows-amd64-setup.exe` 覆盖安装，环境和数据都会保留。
2. **从 0.2.2 应用内更新时，点"安装更新"后请不要手动打开 Cage lite，等它自己重新打开。** 0.2.2 的更新过程没有窗口，提前打开曾导致更新被撤回。从 0.2.3 起，更新过程有自己的窗口。
3. 如果之前的更新留下了 `<安装目录>.cage-installation.json`，并且安装程序提示"存在未处理的安装事务记录"，直接运行 0.2.3 的完整安装包。没有搬移过文件的记录会被自动归档，安装照常进行。
4. 新安装的，在安装选项页勾选"信任 Cage lite 发布者证书"（默认已勾选），Windows 弹出确认时选"是"。也可以手动导入本页附带的 `cage-lite-signing.cer`：

```powershell
Import-Certificate -FilePath .\cage-lite-signing.cer -CertStoreLocation Cert:\CurrentUser\Root
```

## 与 0.2.2 相比

应用更新
- 更新有了自己的窗口：显示版本和"备份、停止环境、安装、启动新版"四步。新版启动后窗口自动关闭；失败时窗口保留结果，可以打开 Cage lite 或导出诊断包。
- 更新期间从桌面、开始菜单或任务栏打开 Cage lite，只会把更新窗口调到前面，不再打断更新。
- 新版在更新期间被提前打开时，不再被误判为"未能完成启动确认"而撤回。
- 撤回更新时如果程序目录被占用，会先结束占用的程序再重试；仍不行就保留已装好的新版，不再留下挡住后续安装的记录。
- 检查更新改为读取发行页附带的版本清单，不再占用 GitHub API 每小时 60 次的额度。同一出口地址的多台电脑不会再互相耗尽额度，出现"更新源请求受限"。
- 更新失败的原因写进事件日志，最近 10 次结果保留在更新目录里，不再只在界面上出现一次。
- 关于页去掉"源码更新"，"发行版更新"显示应用更新器的状态，并可以直接下载和安装。

环境画面
- 客机画面（VNC）不再固定使用主机 15900 端口。Windows 的 WinNAT 或 Hyper-V 保留了这个端口时，画面会一直连不上；现在每次启动时选一个可用端口。

## 校验与源码

- `SHA256SUMS` 列出本页所有文件的 SHA-256；`cage-lite-release.json` 是应用内更新读取的版本清单。
- 安装包内的 mihomo（GPL-3.0）和 QEMU（GPL-2.0）的对应源码附在本页。Cage lite 本身的源码在本仓库，以 MIT 许可发布。
