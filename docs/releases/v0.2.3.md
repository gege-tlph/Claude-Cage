Cage lite 0.2.3，只提供 Windows 版（Windows 10 22H2、Windows 10 LTSC 2021 或 Windows 11，x64）。

## 安装

1. 已装 0.2.2 的，可以在应用内更新，也可以下载 `Cage-0.2.3-windows-amd64-setup.exe` 覆盖安装，环境和数据都会保留。
2. **从 0.2.2 应用内更新时，点"安装更新"后请不要手动打开 Cage lite，等它自己重新打开。** 0.2.2 的更新过程没有窗口，提前打开曾导致更新被撤回。从 0.2.3 起，更新过程有自己的窗口。
3. 如果之前的更新留下了 `<安装目录>.cage-installation.json`，并且安装程序提示"存在未处理的安装事务记录"，直接运行 0.2.3 的完整安装包。没有搬移过文件的记录会被自动归档，安装照常进行。
4. 新安装的，在安装选项页勾选"信任 Cage lite 发布者证书"（默认已勾选），Windows 弹出确认时选"是"。也可以手动导入本页附带的 `cage-lite-signing.cer`：

```powershell
Import-Certificate -FilePath .\cage-lite-signing.cer -CertStoreLocation Cert:\CurrentUser\Root
```

## 与 0.2.2 相比

应用更新
- 更新有了自己的窗口：显示版本和"备份、停止环境、安装、启动新版"四步。新版启动后窗口自动关闭；失败时窗口保留结果，可以打开 Cage lite 或导出诊断包。
- 更新期间从桌面、开始菜单或任务栏打开 Cage lite，只会把更新窗口调到前面，不再打断更新。更新窗口被其他窗口挡住时会显示到最前面，但不抢键盘输入。
- 新版在更新期间被提前打开时，不再被误判为"未能完成启动确认"而撤回。
- 安装程序替换文件前，会关掉更新期间又打开的旧版 Cage lite 窗口（只关窗口，后台和虚拟机不动）。以前这个旧窗口会让新版无法完成启动确认，更新被撤回；从 0.2.2 更新到 0.2.3 时这一条已经生效。
- 撤回更新时如果程序目录被占用，会先结束占用的程序再重试；仍不行就保留已装好的新版，不再留下挡住后续安装的记录。
- 撤回更新时，Cage lite 窗口被关闭后后台会进入锁定状态，曾导致后台拒绝停止、撤回失败。现在空闲的后台直接交接退出，不再需要解锁。
- 撤回由更新前的版本执行，所以上面两条从 0.2.3 更新到之后的版本时才生效。
- 点了安装以后，更新窗口出现在最前面，不再被浏览器等窗口盖住；更新失败时任务栏按钮会闪烁。同样从 0.2.3 更新到之后的版本时生效。
- 检查更新改为读取发行页附带的版本清单，不再占用 GitHub API 每小时 60 次的额度。同一出口地址的多台电脑不会再互相耗尽额度，出现"更新源请求受限"。
- 更新失败的原因写进事件日志，最近 10 次结果保留在更新目录里，不再只在界面上出现一次。
- 关于页去掉"源码更新"，"发行版更新"显示应用更新器的状态，并可以直接下载和安装。
- 带 `/DIAGNOSTICS=<文件>` 运行安装程序时，解压程序文件失败会在诊断文件里记下第一个没写完的文件、已写入的文件数和磁盘剩余空间，之后删除临时解压目录。受限自动化环境里静默安装无法运行时的替代办法见 `docs/windows.md`。

环境画面
- 客机画面（VNC）不再固定使用主机 15900 端口。Windows 的 WinNAT 或 Hyper-V 保留了这个端口时，画面会一直连不上；现在每次启动时选一个可用端口。

工作台
- 启动失败卡片的正文不再重复标题，超过三行时折叠，可展开；查看检查清单、恢复选项和操作详情收在卡片底部一行。
- 联网检查失败时，多个出口检测服务的相同原因只说一次，例如"6 个出口检测服务均失败（连接在返回完整结果前中断）"。
- 侧栏项目操作栏改为"新建终端"加"更多"菜单，项目可以置顶、快速重命名；项目选择框里每一行都能直接编辑或移除。
- 只有一个 Desktop 实例时，侧栏平铺显示；新建第二个实例后改为树状。
- 内置浏览器里 Shift+点击在新窗口打开的链接，工作台会切到这个新标签。
- Cookie 管理在同一网站内换页、设置页切换分类时，不再报"网页已切换"；换到别的网站时列表自动刷新。
- 安装目录换过以后（装到别处或换过安装包），旧目录留下的代理核心记录不再让每次启动都失败。
- 订阅下载失败时，诊断包的事件日志里会写明底层原因（连接被拒、证书、超时等），以前只有"订阅下载失败"。

英文界面
- 安全检查清单、设备检查、初始化检查、环境清理和插件同步不再显示中文。
- 后台、客机脚本和 Windows 应用约 2,400 条报错和提示补上了英文，拼接出来的报错按模板翻译。

Ferry
- 首次设置的第一屏可以选"从 Cage 配置"或"从 Ferry 配置"。选 Ferry 时，填好自己的订阅作为前置，再填 Ferry 用户名和密码；Cage lite 会自动建账户、导入并连接前置、登录 Ferry、导入出口，组成"同地区前置 → Ferry 出口"的代理链。
- "网络代理"页新增"从 Ferry 导入"卡片：中途中断后可以接着做，显示是否在用 Ferry 出口，可以恢复链路或重新选前置；账号到期或停用时也会显示。
- 与 Ferry 的通信只走前置。Ferry 的出口变了，代理链跟着换；出口每 5 分钟检查一次，连续两次不通就立刻更新 Ferry 订阅。

Windows 与网络（来自上游）
- 安装目录在 exFAT 或 FAT32 分区上时，安装事务的回执删不掉，之后的安装、更新和卸载都会被挡住。现在能正常完成。已经被挡住的 0.2.2 用户，需要先手动删除 `<安装目录>.cage-installation.json`，再运行 0.2.3 安装包。
- Windows 用户名含中文等非英文字符、又没有可用的英文短文件名时，本机控制通道找不到私有目录，"应用代理"失败、外网一直关闭。现在改用系统盘上仅当前用户可访问的备用目录。
- 安装路径含韩文等系统代码页以外的字符时，QEMU 找不到固件，环境无法启动。现在能正常加载。
- 配置了多个加密 DNS 端点时，在客机超时前就切换到备用端点。
- 出口探测保留"服务器返回了明文 HTTP"这一原因；代理核心不再继承主机的代理环境变量。
- 启动时清理崩溃遗留的候选代理核心和临时目录。
- 首次启动先检查代理出口，出口不通时直接说明，不再表现为系统镜像下载失败；首次安装显示 Debian 软件索引下载和基础依赖安装两个阶段。
- 大安装包的 APT 下载增加有界重试，失败时说明缓存里还有多少没下载完。
- 网络慢时首次安装，只要下载一直有进展，就不会在 10 分钟后被判为"启动 Linux 基础环境失败"。
- 更新或撤回时停止环境，会等满虚拟机自己的关机时间，不再因为关机稍慢而取消更新。
- 环境已停止时验证代理出口，提示先启动环境。
- 共享项目里大仓库的 `git status` 和目录遍历更快：只读的文件请求并发处理，不存在的路径缓存 20 秒，客机 Git 默认不再因主机和客机的文件时间差异重算整个索引（上游 #1062）。
- 去掉早已不起作用的 `.git` 只读保护和命令行选项 `--unsafe-writable-git`（上游 #1061）。

代理导入
- 从本机 Clash 类软件导入时，配置里的 `hosts` 别名会展开成实际地址（TLS 名称不变）。
- 中转（`dialer-proxy`）指向策略组的节点不再被跳过，按组内当前选中的节点导入（Clash Verge Rev 记下的选择，没有就取第一个），配置卡片上标出"中转分组「X」导入为「Y」"。

代理导入（来自上游）
- 支持导入 Shadowrocket 导出的 VLESS 和 VMess 分享链接。
- 节点的 DNS 地址末尾带 `#DIRECT` 时也能导入。
- 能读取放在配置目录里、用绝对路径引用的 provider 缓存。

## 校验与源码

- `SHA256SUMS` 列出本页所有文件的 SHA-256；`cage-lite-release.json` 是应用内更新读取的版本清单。
